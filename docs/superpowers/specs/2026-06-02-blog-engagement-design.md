# Стратегия вовлечения блога: комментарии + Яндекс.Дзен

## Контекст и цель

Блог pro-pochvu вырос до 32 статей (хаб с рубриками/подборками/тегами, в т.ч. 12 статей
по материалам партнёрского канала @spottykit). Нужно повысить вовлечённость аудитории и
усилить четыре бизнес-цели одновременно: **трафик/SEO**, **повторные продажи/LTV**,
**сбор собственной аудитории** (не зависеть только от маркетплейсов и Telegram) и
**бренд/доверие**.

Ограничение, заданное заказчиком: **минимум регулярного труда, автоматизация**. Нет
выделенного человека на модерацию/ведение. Поэтому всё проектируется так, чтобы работать
почти без ручного вмешательства.

Концепт «клуба/сообщества» **исключён из scope** осознанно: у партнёра (Екатерина,
@spottykit) уже есть собственный платный «Зелёный клуб» / «Зелёная семья» — своё
сообщество конкурировало бы с партнёром и требовало бы community-менеджмента, которого нет.

Стратегия = два инструмента: **(1) собственные комментарии в блоге** и
**(2) Яндекс.Дзен как канал републикации с переходами на сайт**.

## Принятые решения (вводные)

- Комментарии — **свои** (в нашей БД), не сторонний виджет: только они рендерятся на
  сервере и **индексируются** поисковиками (копят НЧ-запросы, растят поведенческие) →
  работают на SEO-цель. Сторонние виджеты (Disqus/Cackle) и Telegram-обсуждения не
  индексируются; Telegram вдобавок упирается в блокировку РКН (та же проблема, что решали
  фолбэком в `TelegramPost`).
- Комментарии — **анонимные с премодерацией** (имя + текст, публикация после проверки).
  Премодерация уживается с «минимумом труда» за счёт автоматики: спам отсекается
  автофильтром и не попадает в очередь; одобрение легитимных — в один клик из Telegram.
- Дзен — **полный текст статьи со ссылками внутри** (больше охват внутри Дзена), а не
  тизер-анонс.

## Архитектура

Две фазы. Фаза 1 (комментарии) — основная сборка, самодостаточна. Фаза 2 (Дзен) — мало
кода + операционный плейбук.

### Фаза 1 — Комментарии

#### 1.1 Модель данных

Новая Prisma-модель `BlogComment`:

| Поле | Тип | Назначение |
|---|---|---|
| `id` | String @id @default(cuid()) | PK |
| `postSlug` | String | связь со статьёй; `post BlogPost @relation(fields:[postSlug], references:[slug], onDelete: Cascade)` |
| `authorName` | String | имя автора (2–60 символов) |
| `authorEmail` | String? | опционально; **никогда не отображается**; для будущих уведомлений об ответах |
| `body` | String @db.Text | текст (3–2000 символов) |
| `status` | CommentStatus | `PENDING` \| `APPROVED` \| `REJECTED` |
| `createdAt` | DateTime @default(now()) | |
| `approvedAt` | DateTime? | момент одобрения |
| `ipHash` | String? | хэш IP (SHA-256 с серверной солью) для rate-limit/абьюза — **не сырой IP** |
| `moderationToken` | String @unique | случайный токен для одно-кликовой модерации из Telegram |

- `enum CommentStatus { PENDING APPROVED REJECTED }`
- `@@index([postSlug, status, createdAt])`
- В `BlogPost` добавить обратную связь `comments BlogComment[]`.
- Миграция Prisma + регенерация клиента.

#### 1.2 Отправка + автомодерация — `POST /api/blog/comments`

Валидация Zod: `postSlug` (существует и опубликована), `authorName`, `body`, `consent`
(=== true), `website` (honeypot — должен быть пустым), `authorEmail` (опц., формат email).

Конвейер обработки (по порядку, первый сработавший фильтр завершает):

1. **Honeypot**: поле `website` заполнено → тихо вернуть `200` с обычным сообщением (бот
   думает, что успех), комментарий не сохраняется.
2. **Rate-limit** по `ipHash`: не более 3 комментариев за 10 минут и 10 за сутки → `429`.
3. **Эвристики спама** → авто-`REJECT` (сохраняем со статусом REJECTED для статистики,
   пользователю — нейтральный ответ):
   - наличие URL/ссылок в `body` (анонимным комментаторам ссылки почти не нужны, спам —
     почти всегда со ссылками);
   - стоп-слова (профанити/типичный спам — список в коде, расширяемый);
   - аномалии: сплошной капс, длинные повторы символов, доля латиницы выше порога при
     RU-аудитории.
4. Прошедшие фильтры → статус **PENDING**, генерируется `moderationToken`, сохраняется
   (`ipHash`, без сырого IP).
5. **Уведомление в Telegram** через существующий `src/lib/telegram.ts`: заголовок статьи,
   имя автора, фрагмент текста и две токен-ссылки (одобрить / отклонить).

Ответ API **всегда** нейтральный: «Комментарий отправлен на модерацию» — и для PENDING, и
для авто-REJECT (чтобы не давать спамеру обратную связь). Валидационные ошибки → `422`.

*Опционально, отдельной итерацией (не в v1):* AI-классификация спорных комментариев через
Claude API за фиче-флагом `COMMENTS_AI_MODERATION` (по умолчанию выключено — бесплатно и
без внешних зависимостей).

#### 1.3 Модерация в один клик — `GET /api/blog/comments/[id]/moderate`

Параметры: `token`, `action` (`approve` | `reject`). `moderationToken` и есть авторизация
(привязан к конкретному комментарию, неугадываемый) — логин не нужен. Действие:

- сверить токен с комментарием (иначе `403`);
- `approve` → `status=APPROVED`, `approvedAt=now`; `reject` → `status=REJECTED`;
- `revalidatePath('/blog/[slug]')` целевой статьи, чтобы SSR-страница обновилась;
- вернуть крошечную HTML-страницу-подтверждение («Комментарий одобрен/отклонён»).

Это и есть весь рабочий процесс модерации — прямо из Telegram-уведомления.

*Опционально (фаза 1.5):* минимальная страница `/admin/comments` (role=admin через
существующий `middleware.ts`) со списком PENDING и кнопками для батч-разбора. В v1 не
обязательна — токен-ссылок достаточно.

#### 1.4 Рендеринг на `/blog/[slug]` + 152-ФЗ

- На сервере (в существующем server-component статьи) дозапрашиваются `APPROVED`-комментарии
  по `postSlug`, рендерятся под статьёй (**SSR → индексируются**). Заголовок «Комментарии (N)».
  Пустое состояние: «Будьте первым, кто оставит комментарий».
- Форма комментария — отдельный **client-компонент** `BlogCommentForm`: поля имя, текст,
  опц. email, `ConsentCheckbox` (существующий `src/components/ui/`), скрытый honeypot
  `website`. POST на API; при успехе — сообщение «отправлено на модерацию», форма очищается.
- **152-ФЗ**: имя (+ опц. email, + ipHash) — персональные данные. Обязательный чекбокс
  согласия со ссылкой на `/privacy`; email и IP-хэш никогда не показываются публично;
  раздел `/privacy` дополняется описанием обработки данных комментариев и срока хранения.
- **SEO**: JSON-LD статьи (`src/app/blog/[slug]/page.tsx`) расширяется `commentCount` и
  массивом верхних комментариев (`Comment` schema) — потенциальные rich-результаты.

#### 1.5 Затрагиваемые файлы (Фаза 1)

- `prisma/schema.prisma` — модель `BlogComment` + enum + связь; миграция.
- `src/app/api/blog/comments/route.ts` — POST (отправка + автомодерация).
- `src/app/api/blog/comments/[id]/moderate/route.ts` — GET (токен-модерация).
- `src/lib/comments.ts` — конвейер автомодерации (honeypot, rate-limit, эвристики), хэш IP,
  генерация токена. Изолированный, тестируемый модуль.
- `src/lib/telegram.ts` — добавить `notifyNewComment()` (по образцу существующих notify-функций).
- `src/components/blog/BlogCommentForm.tsx` — client-форма.
- `src/components/blog/BlogComments.tsx` — серверный список комментариев.
- `src/app/blog/[slug]/page.tsx` — встроить список + форму + JSON-LD commentCount.
- `src/app/privacy/page.tsx` — раздел про данные комментариев.
- (опц. 1.5) `src/app/admin/comments/page.tsx`.

### Фаза 2 — Яндекс.Дзен

#### 2.1 Код

- RSS-фид `src/app/blog/feed.xml/route.ts` (Route Handler, `Content-Type: application/rss+xml`):
  RSS 2.0, только `isPublished` статьи, полный текст в `content:encoded` (HTML из markdown),
  `title`, `link` (канонический URL статьи), `pubDate`, `guid`. Внутренние ссылки на
  товары/разделы из тела статьи сохраняются.

#### 2.2 Операционный плейбук (разовая ручная настройка — Павел/Катя)

- Создать канал «Пропочву» в Дзене.
- Подключить **импорт из RSS** в настройках канала, фид `https://pro-pochvu.ru/blog/feed.xml`
  (на момент настройки **проверить**, что Дзен поддерживает RSS-импорт; если нет — публиковать
  copy-paste из готового текста статьи).
- **Гигиена дублей**: публиковать в Дзен с задержкой относительно публикации на сайте, чтобы
  наша страница проиндексировалась первой — она оригинал/канонический источник.
- **Ссылки**: в каждой статье 2–3 контекстные ссылки на товары/разделы (как сейчас).
- **Замер**: в Яндекс.Метрике отслеживать переходы с `dzen.ru` (referral-канал) и настроить
  цель клика на товар со страниц с этим источником.
- **Частота**: 2–4 публикации в неделю, сначала из бэклога 32 статей, затем новые по мере выхода.

## Границы (scope)

**В scope:** собственные комментарии (модель, API, автомодерация, Telegram-одобрение,
рендеринг, 152-ФЗ, JSON-LD), RSS-фид для Дзена, операционный плейбук Дзена.

**Вне scope (YAGNI):** ветки/ответы на комментарии, лайки/голосование, профили
комментаторов, редактирование комментариев пользователем, клуб/сообщество, AI-модерация
(опционально позже за флагом), автопостинг в Дзен через API (только RSS/ручной).

## Обработка ошибок

- API комментариев: `422` валидация, `429` rate-limit, `200` нейтральный ответ для
  принятых и авто-отклонённых, `500` только с логированием.
- Модерация: `403` при неверном токене, идемпотентность (повторный клик по уже
  обработанному — не падает, показывает текущий статус).
- Telegram-уведомление недоступно (mock-режим без токенов) → комментарий всё равно
  сохраняется в PENDING (модерация через `/admin/comments` или прямой токен из БД).
- RSS-фид: при ошибке БД отдавать пустой валидный фид, не `500`.

## Тестирование (end-to-end)

- **Автомодерация** (`src/lib/comments.ts`): unit-тесты на honeypot, rate-limit, каждую
  эвристику (ссылка → reject, чистый → pending, капс/латиница).
- **Поток комментария**: POST чистого → PENDING + запись в БД; POST со ссылкой → REJECTED;
  honeypot → не сохранён. Проверить нейтральность ответа.
- **Модерация**: approve по токену → APPROVED + появляется на странице (после revalidate);
  неверный токен → 403; повторный клик идемпотентен.
- **Рендеринг**: на проде (через chrome-devtools) открыть статью — APPROVED-комментарии
  видны в SSR-HTML (проверить, что в исходнике, не только в JS), форма работает, чекбокс
  152-ФЗ обязателен, в `view-source` присутствует JSON-LD `commentCount`.
- **RSS**: `/blog/feed.xml` — валидный RSS 2.0 (валидатор), полный контент, только
  опубликованные статьи, корректные ссылки.
- Перед коммитом: `npm run lint`, `npx prisma validate`, `npx tsc --noEmit`. Сборка/деплой —
  через CI (локальный build на хосте падает SIGBUS), проверка вживую на проде.

## Порядок реализации

1. Фаза 1 (комментарии) — целиком, это основная ценность для всех четырёх целей сразу.
2. Фаза 2 (Дзен) — RSS-эндпоинт + плейбук, после того как комментарии в бою.
