# Скилл `blog-article` — конвейер SEO-статей из заметок @spottykit

## Проблема

Публикация статей в блог pro-pochvu из контента партнёрского канала @spottykit обкатана вручную (2 батча = 12 статей), но каждый раз воспроизводится по памяти: выбрать темы из дайджеста, написать в фирменном стиле без AI-следов, подобрать обложку с кредитом, сгенерить seed-скрипт, задеплоить на прод, пнуть IndexNow, обновить учёт. Нужен скилл, кодифицирующий этот процесс — автономный, с соблюдением стиля так, чтобы тексты не читались как сгенерированные Клодом.

## Решения (зафиксированы с Павлом)

- **Автономность:** полностью автономно — скилл сам выбирает темы, пишет, ставит обложки, деплоит. Без чекпоинтов.
- **Обложки:** тематический матч к существующим 19 (Pexels, self-hosted в `/public/images/blog/`) + копия кредита. Новые не скачивает; если подходящей нет — флажок «нужно фото» (плейсхолдер, Павел добавит вручную).
- **Деплой:** внутри скилла (seed прод + push blog.ts + IndexNow).
- **Батч:** 3 статьи по умолчанию (параметризуемо).
- **Дедуп:** live-список опубликованных slug из прод-БД (источник истины).

## Workflow

### 1. Выбор тем
- Читать `docs/partner-content/spottykit/relevant-digest.md` (84 релевантных поста с текстом/ID).
- Тянуть live-список опубликованных slug из прод-БД: `ssh spb1 "docker exec ecokon-db psql -U <user> -d <db> -tAc 'SELECT slug FROM \"BlogPost\";'"` (точную строку подключения взять из env контейнера).
- Дедуп против опубликованных + против списка «уже использовано» в памяти `partner-spottykit-content.md`.
- Выбрать N (=3) релевантных тем под категории сайта: `udobreniya` / `grunty` / `tsvetologiya` / `uhod`. Остаток тем для старта — в памяти (спатифиллум, петунии, закаливание/вынос на улицу, долгоиграющие удобрения, крупномеры, орхидея после цветения).

### 2. Написание (по `references/style-guide.md`)
Каждая статья:
- **Структура:** тёплый ввод-крючок (сенсорный/житейский, без «В этой статье мы рассмотрим») → секции `##` → болд-лейблы внутри (`**Свет** — …`) → блок `## Частые вопросы` с 3 Q/A (под FAQ-разметку) → футер-атрибуция @spottykit.
- **Линковка:** 2–4 внутренние ссылки на существующие статьи блога (`/blog/<slug>`) + 1–2 product-анкора (`/product/<slug>` или `/catalog/<line>`). Ссылки только на реально существующие URL (проверять по прод-БД / каталогу).
- **Длина:** ~500–900 слов, как в обкатанных батчах.
- **Язык/тон:** русский, экспертный но доступный; базовые понятия не разжёвывать.
- **Анти-AI-следы:** прогон по чеклисту style-guide (без «играет важную роль», «стоит отметить», «в современном мире», рул-оф-три, избыток тире, пустых заключений-обобщений) + применить принципы скилла `humanizer` к финальному тексту.
- **Поля:** slug (латиница-транслит), title, excerpt, category, tags[], coverImage, seoTitle, seoDescription, publishedAt, content.

### 3. Обложки
- Для каждой статьи подобрать по теме одну из 19 существующих (`/images/blog/*.jpg`, карта тем — `update-blog-covers.ts` + `BLOG_IMAGE_CREDITS`).
- Скопировать кредит исходной обложки в `BLOG_IMAGE_CREDITS[slug]` (author + Pexels source).
- Если тема визуально не покрывается ни одной из 19 → coverImage = ближайшая тематическая + пометка в выводе «нужно фото для <slug>» (Павел заменит, как делали с Pexels-загрузками).

### 4. Обвязка (правки в репо)
- Сгенерить `scripts/seed-blog-batchN-spottykit-YYYYMM.ts` по структуре `seed-blog-batch2-spottykit-202606.ts` (ATTRIBUTION-константа, `upsert` по slug, тип `Article`).
- Дописать в `src/lib/blog.ts`: `BLOG_PRODUCT_ANCHORS[slug]` (товар для CTA-блока) и `BLOG_IMAGE_CREDITS[slug]`.

### 5. Публикация
- **Прод-seed (контент в выдаче сразу):** `scp scripts/seed-… spb1:/tmp/` → `docker cp /tmp/seed-… ecokon-web:/app/scripts/` → `docker exec -w /app ecokon-web npx tsx scripts/seed-…`. На таймаут ssh — retry (см. `references/publish.md`).
- **Код (кредиты/анкоры):** `git add` seed + blog.ts → commit → push main → CI-деплой (~9 мин).
- **IndexNow:** `POST /api/indexnow/ping` с массивом новых URL (токен `ADMIN_API_TOKEN` из контейнера) или bulk.

### 6. Учёт
- Обновить память `partner-spottykit-content.md`: добавить новые темы в «уже использовано», убрать из «остатка».
- Обновить `docs/CONTENT_PLAN.md` (статусы).
- Залогировать через скилл `log` (дейли + при вехе _SUMMARY).

## Структура скилла

```
~/.claude/skills/blog-article/
  SKILL.md                  # процесс (этот workflow в исполняемом виде)
  references/
    style-guide.md          # голос бренда, шаблон структуры, чеклист анти-AI-следов, примеры из живых статей
    publish.md              # ранбук: команды прод-seed (retry на ssh-таймаут), push, IndexNow, psql-дедуп
```

`SKILL.md` — короткий процедурный костяк со ссылками на references. Тяжёлый стиль-гайд и команды деплоя вынесены, чтобы не раздувать основной файл и грузить их по необходимости.

## Границы (YAGNI)

- Только пайплайн @spottykit → блог. Не обобщаем на произвольные источники сейчас.
- Не скачиваем новые фото автоматически (Pexels API-ключ не заводим) — переиспользуем существующие, новое фото — ручной шаг Павла.
- Не трогаем структуру блога (хаб/рубрики/теги) — она готова.

## Критерии успеха

- Запуск скилла без аргументов → 3 новые статьи опубликованы на проде, видны на `/blog`, в нужных рубриках, с рабочими внутренними и product-ссылками, обложкой и кредитом, атрибуцией @spottykit, FAQ-блоком.
- Тексты проходят чеклист анти-AI-следов (выборочная вычитка не выдаёт генерацию).
- Дедуп: ни одна тема не повторяет уже опубликованную.
- Память и CONTENT_PLAN обновлены, IndexNow пнут.
